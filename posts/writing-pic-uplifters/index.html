Writing Pic Uplifters
Damn It's Hard!

published on Fri, Apr 21, 2023 | 10 minutes read

  • Posts
  • Writing Pic Uplifters

In last post we went through the general reference manual. Turns out (after going through some datasheets), it’s better to divide the whole IL uplifting process into families like :

  • PIC16FXXXX
  • PIC18FXXXX
  • PIC32FXXXX (completely different device!, take a look)
  • etc…

Why? Well because I went through the datasheets and it looks like the reference manual we referred to is outdated and new devices were added to family with more memory banks! I noticed some datasheets specifying that the given device has 32, 64, 128 etc… memory banks! The reference manual states there are only 4 memory banks in each device in family. Well, I did find some devices with 4 memory banks but now I think that since it’s hard to find which device belongs to which family (since manual states devices starting with name pic16f but clearly new devices don’t follow the manual), it’s better to split them based on device initials instead of mid-range, base-line and high-end.

Keep in mind that we eventually want to uplift all Mid-Range devices even though it doesn’t seem like so atm. We’ll need datasheets of PIC16CXXXX etc… too but let’s worry about those later. For now, we’ll uplift only PIC16FXXXX devices.

Now I just have to go through these datasheets one by one and get their memory map and instruction set. One more advantage of this process is that we can get exact idea of which instructions a chip supports and which ones it doesn’t. This might help improve analysis by detecting faulty instructions.

Improvising Previous Plan

Previously I was setting register map like a string array and assumed that it’ll be same for all devices but now I think, since register types are same across each of these devices (not verified) and only memory map and supported instruction set is changing (verified) we can create an enum of register types, create a lookup table to map from these enums to their string values and then define the memory/register maps using these enums. This way to add new devices we just need to add new memory maps! Ez Pz af.

Here’s the register enum types :

#define GET_WREG() VARG("WREG")

Get Register Type & RzILOpPure For Given Register

// device to register schema map
const char **pic_midrange_device_reg_map[] = {
    [PIC16F882] = pic16f882_reg_map,
    [PIC16F883] = pic16f883_reg_map,
    [PIC16F884] = pic16f884_reg_map,
    [PIC16F886] = pic16f886_reg_map,
    [PIC16F887] = pic16f887_reg_map,
};

/**
 * Get PicMidrangeRegType corresponding to give register index
 *
 * \param cpu_state Device CPU state.
 * \param regidx Register index inside given bank of given device type.
 *
 * \return PicMidrangeRegType
 * */
PicMidrangeRegType pic_midrange_il_get_reg_type(RZ_NONNULL PicMidrangeCPUState *cpu_state, ut8 regidx) {
    rz_return_val_if_fail(cpu_state, REG_INVALID);

    // compute linear register address
    ut32 addr = cpu_state->selected_bank * BANK_SIZE + regidx;
    return pic_midrange_device_reg_map[cpu_state->device_type][addr];
}

/**
 * Get RzILOpPure corresponding to given register index of given device type.
 *
 * \param cpu_state Device CPU state.
 * \paramm regidx Register index in given memory bank of given device type.
 *
 * \return valid RzILOpPure on success, NULL otherwise.
 * */
RzILOpPure *pic_midrange_il_get_reg(RZ_NONNULL PicMidrangeCPUState *cpu_state, ut8 bank, ut8 regidx) {
    rz_return_val_if_fail(cpu_state, NULL);

    // compute linear address
    ut32 addr = cpu_state->selected_bank * BANK_SIZE + regidx;
    PicMidrangeRegType reg_type = pic_midrange_device_reg_map[device_type][addr];

    // return register for given type
    if(reg_type == REG_FREG) {
        return GET_FREG(addr);
    } else {
        // this will also handle REG_UNIMPLEMENTED & REG_RESERVED automatically.
        return GET_SPREG(pic_midrange_il_regnames[reg_type])
    }
}

// use only in IL_LIFTER functions
#define GET_REG_TYPE(idx) pic_midrange_il_get_reg_type(cpu_state, idx)
#define GET_REG(idx) pic_midrange_il_get_reg(cpu_state, idx);

Now, at this point, we can either write a sequence of operations like pic_midrage_il_get_reg(ut8 idx) which’ll automatically query the bank, convert idx to a U8 and compute effective linear address of register. This way we get to use the register’s linear address as it’s identifier and we also won’t be able to check if given register is an UNIMPLEMENTED or a RESERVED register that both read value 0 when accessed. In current way of things, we can easily differentiate between these two cases!

Checking For Carry Flag

This part took me some time to understand. I never paid much attention to use of overflow and carry flag. Let me make things simple for you.

  • The term carry means the addition of two unsigned numbers was not able to fit in given area and hence the result is wrong.
  • The term overflow means the addition of two signed numbers was not able to fit and we got a wrong result. Remember that in signed arithmetic, the most significant bit gives you the sign of given 2’s complement number.
  • ALU doesn’t care about your signed or unsigned arithmetic so it’ll set both these flags for each operation that can and must affect these flags. This means we need to capture this too while uplifting!

Please refer to this blog post to get detailed understanding of how to detect an overflow or a carry using bitwise logical operators only!

ADDWF Uplifter

Finally we compile everything we built up until now and use that to write an ADDWF uplifter. Notice how we set flags by keeping a backup of old value of WREG register and using the newly defined SET_STATUS_ADD macro that’ll return RzILOpEffect sequence of instructions to set required flags.

/**
 * ADDWF
 * Operation: Add FREG to WREG.
 * Operands: f, d
 * Status affected : C, DC, Z
 * */
IL_LIFTER(ADDWF) {
    // get register type
    ut8 regidx = PIC_MIDRANGE_OP_ARGS_7F_GET_F(instr);
    ut8 addr = cpu_state->selected_bank * BANK_SIZE + regidx;
    PicMidrangeRegType reg_type = GET_REG_TYPE(addr);

    // create a copy of current value of wreg since it's going to change
    RzILOpEffect *wreg_old = SETL("wreg_old", GET_WREG());
    RzILOpEffect *add_op = NULL;
    RzILOpEffect *set_status_op = NULL;

    // if this is an unimplemented or reserved register then
    // it's read as 0
    if(reg_type == REG_UNIMPLEMENTED || reg_type == REG_RESERVED) {
        add_op = ADD(GET_WREG(), U8(0));
        set_status_op = SET_STATUS_ADD(GET_WREG(), VARL("wreg_old"), U8(0));
    } else {
        add_op = ADD(GET_WREG(), GET_REG(idx))
        set_status_op = SET_STATUS_ADD(GET_WREG(), VARL("wreg_old"), GET_REG(idx));
    }

    return SEQ2(add_op, set_status_op);
}
