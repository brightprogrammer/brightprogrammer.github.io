How PIC Works & Where Is It Used?

Here are some resources I initially used to gain general idea of things :

  • First and major resources pointing to other resources is Wikipedia
  • Next this video introduced me to basic assembly and how to use PIC devices.
  • Architecture Manual itself.

After getting to know more about I understood the following things :

  • PIC is used in embedded systems
  • Has different chip varieties in same family for allowing different selections for different use cases.
  • At present all devices are categories into three categories :
    • PIC Base-Line
    • PIC Mid-Range
    • PIC High-End
  • Due to different devices in each of these varieties, the whole manual is broken into two document types :
    • Family Reference Manual : Describe an overall general structure of chip. For understanding memory model, registers etc… we might need datasheets
    • Datasheets : Describe information that are specific to device.
      • Which ports are active and which ones aren’t.
      • Which registers are implemented.
      • How many pages of memory are there?
      • Which instructions are not supported (maybe, didn’t go through datasheets yet because there are 100s of them!)
  • Things like instruction size, register size etc… don’t change in same family.
  • There’s also a naming convention for each family that is present in the beginning few pages of reference manual. This is not useful for this project probably but useful if you just want to understand the PIC architecture.
    • PIC16CXXX stands for EPROM type memory.
    • PIC16CRXXX stands for ROM type memory.
    • PIC16FXXX stands for flash type memory
  • There are other less important (for this project) details mentioned like how you can select and publish your product and all…
Important Note

When learning an architecture for the first time, always properly go through the contents of manual first! This will help you gain insight on what things are present where and how you can go through the manual strategically. When I started writing a disassembler for x86, I spent lot of time just finding the x86 instruction format and later I realized that if only I had went through the contents of each volume first.

P.S. : x86 manual is more than 3000 pages! and 5000 pages for Intel's version!

Understanding Memory Model

  • Architecture : Harvard Architecture
  • Endianness : Don’t care, but I’ll assume it to be Little Endian
  • Memory Types :
    • Program Memory
      • Each instruction is 14 bits in size.
      • Program Counter (PC) register is 13 bits in size to index 8K instructions.
        • Program counter is broken into two 8 bit registers | PCH | PCL |
        • There’s also a PCLATH (Program Counter Latch High) that is used to calculate actual instruction address.
          taken from PIC Mid-Range reference manual
          ———————————————————————–
        • Since size of each instruction is fixed, a 14-bit quantum is called an Instruction Word in Program Memory.
        • Also, since these instructions are quantum, PC just needs to specify the integral index of the instruction it wants to fetch.
      • Program memory bus is 14-bits in size in order to be able to fetch a single 14-bit instruction.
      • HardWare Call Stack
        • The call stack can go maximum 8 level deep.
        • This means 9th depth call will overwrite the top most value on stack, 10th will overwrite the 2nd from top and so on.
        • There is no check present to make sure there was a call stack curroption!
          taken from PIC Mid-Range reference manual
          ———————————————————————–
          taken from PIC Mid-Range reference manual
          ———————————————————————–
      • This 8K instruction region is not completely implemented in all devices belonging to same family.
      • The program memory is divided into 4x2K memory regions called a Page.
      • If program counter crosses the implemented memory region, it’ll wrap around to the beginning of memory region.
      • It may be possible that not all (program) memory pages are implemented.
      • To jump between memory pages, high bits of PC register must be modified. This is done by the help of PCLATH register. We can specify the page we want to jump to using
        • BSF PCLATH, <bit> : BIT SET FLAG and
        • BCF PCLATH, <bit> : BIT CLEAR FLAG
          taken from PIC Mid-Range reference manual
          ———————————————————————–
    • Data Memory
      • Registers
        • Types :
          • General Purpose Registers (GPR) (multiple)
          • Special Purpose Registers (SPR) (multiple)
          • Working Register (WREG) (only one)
        • Names :
          • Registers are indexed using values in between 0 to 255 instead of having names.
          • Although in IDEs there are multiple defines to name them.
          • GPRs are called File Registers and can be named like FREG#num or F#num
          • SPRs have special names in Reference Manual
          • WREG is named WREG or just W.
          • Size of each register is 8 bits (1 BYTE)
          • Data Memory is divided into four parts. Each part is called a Memory Bank.
            • Each memory bank is very similar to each other and follow the same template.
            • There are some common (implemented) registers and some unimplemented registers.
            • One can switch between memory banks by using <RP1>:<RP0> bits in the STATUS register or the IRP bit.
            • This architectural feature gives rise to two addressing modes :
              • Direct Addressing Mode : Use <RP1>:<RP0> bits of STATUS register. Used when exact address is known at runtime.
              • Indirect Addressing Mode : Use <IRP> bit of STATUS register to specify PAGE0/PAGE1 address or PAGE2/PAGE3 address. Used when address is to be calculated at runtime.
      • Some registers are present in all devices of same family but some aren’t. Not present registers (unusable ones) are called unimplemented in reference manual and reading them will give 0.
        taken from given PIC Mid-Range reference manual
        —————————————————————————–
  • There are two different and separate memory BUS to access each of these two memory regions.

Interrupts, Exceptions & Device Resets

Yes, there are exceptions & interrupts in PIC devices too! They generally occur due to some arithmetic instruction error or some other common cases. There are reset flags to inform program that a specific interrupt occured. Please take reference in manual for this. Understanding this is not that important now as we can reiterate over this when writing uplifters.

There are also detailed tables that give the initial value of each registers at the time of initialization. This is good because we’ll need this when writing uplifters.

Instruction Format

This is discussed in Section 5 & Section 29 of Reference Manual. It specifies different types of instructions, their arguments and their format.

Three types of instructions :

  • Byte-Oriented operations
  • Bit-Oriented operations
  • Literal or Control operations

For byte-oriented instructions, ‘f’ represents a file register designator and ‘d’ represents a destination designator.

  • The file register designator specifies which file register is to be used by the instruction.
  • The destination designator specifies where the result of the operation is to be placed.
  • If ‘d’ is zero, the result is placed in the W register.
  • If ‘d’ is one, the result is placed in the file register specified in the instruction.

For bit-oriented instructions, ‘b’ represents a bit field designator which selects the number of the bit affected by the operation, while ‘f’ represents the number of the file in which the bit is located.

For literal and control operations, ‘k’ represents an eight or eleven bit constant or literal value.
Taken from PIC Mid-Range Reference Manual
